# 同平台多账号（多个飞书 / Telegram 机器人并行）

> issue #78 功能说明与使用指南。自 v2.15.0 起，同一台机器、同一个 DSH 里可以同时挂**多个同平台机器人**（例如两个飞书自建应用「小鲸」与「小秤」），各自的凭证、人设、工作区、白名单与会话归属完全隔离。

---

## 🌟 适用场景

| 场景 | 示例 |
|---|---|
| 一人多助手 | 飞书「工作助手」跑技术/项目管理，飞书「生活助手」只跑家庭日程与提醒 |
| 团队共享部署 | 每个成员一个自己的飞书应用，互不串线、互不可见 |
| 灰度 / 对比 | 同一个 DSH 挂两个应用，一个跑稳定预设，一个跑实验预设 |

此前这类需求只能二选一，或将第二个应用挂到别的插件上，导致同一个 DSH 有两套 IM 通道、两套会话归属。现在一个插件内即可并行。

---

## 🚀 操作步骤（设置面板）

1. 打开 DSH Web 设置页「**远程访问**」→「**IM 机器人**」；
2. 在平台选择栏选择平台（微信 / QQ / 飞书 / Telegram）；
3. 点击平台面板上方的「**＋ 添加账号**」→ 出现一张新的账号卡片；
4. 在新卡片里填入该账号的凭证与配置，点「**保存并连接**」；
5. 需要多个账号时重复 3–4；每个账号独立连接、独立扫码/配对、独立白名单。

> 💡 **单账号用户无感**：只有一个账号时，界面与旧版本一致（进入平台看到一张卡片），仅在卡片顶部多了「账号备注」输入与「移除账号」入口。
>
> 💡 **账号备注**：可留空，留空时按「飞书 1 / 飞书 2 / Telegram 1…」自动编号；填写后（如「小鲸」「小秤」）更易区分。

### 移除账号

账号卡片右上角「**移除账号**」→ 二次确认。移除会：

- 停止该账号的连接并清理其运行状态；
- 从 `config.json` 中删除该账号的凭证、白名单、会话归属等配置；
- **不会**删除 DSH 里已存在的会话（`/sessions` 里仍可见，只是不再自动归属该机器人）。

移除后该平台若已无账号，会显示空状态，可随时「＋ 添加账号」重新添加。

## 🔒 隔离与限制

**每个账号独立**：

- 凭证（App ID / App Secret / Bot Token 等）；
- 工作区（`cwd`）、Agent 预设、模型路由（`agentProvider` / `agentModel`）；
- 白名单（`allowFrom`，审批授权按账号隔离）；
- 活动会话（`activeSessionId`）与会话归属——两个账号不会串到同一个 DSH 会话；
- 斜杠指令注册（飞书 `/help` `/new` 等按应用分别注册与同步）；
- 会话节奏参数（本轮改动摘要间隔、审批超时、分块延时、实时活动状态开关）。

**限制**：

- **同一应用不能重复添加**：飞书 / QQ 按 App ID 查重、Telegram 按 Bot Token 查重；重复时保存会返回「同一应用不能重复添加：该凭证已被「xxx」使用」。同一应用只能有一条长连接是平台侧限制。
- **单平台最多 10 个账号**（每个账号都是一条独立长连接，过多会占用较多内存与网络连接）。
- **微信的重复凭证无法在保存前拦截**：微信按扫码登录、凭证在登录完成后才产生，同一微信号若被两个账号分别扫码，只能在登录后暴露；飞书 / QQ / Telegram 的凭证走保存接口，保存时即拦截。
- 账号之间不共享任何运行状态；DSH 本体（代理端口、访问认证、隧道）仍是全局一套。

## 🗂️ 配置文件结构（config.json）

多账号配置位于 `~/.dsh/dsh-bridge/config.json`，各平台从「单对象」升级为「账号数组 + 序号」：

```json
{
  "feishu": {
    "accounts": [
      {
        "instanceId": "feishu",
        "name": "小鲸",
        "appId": "cli_xxx",
        "appSecret": "***",
        "domain": "feishu",
        "allowFrom": ["ou_xxx"],
        "activeSessionId": "session-id",
        "agentPreset": "remote",
        "cwd": "/home/me/work"
      },
      {
        "instanceId": "feishu:2",
        "name": "小秤",
        "appId": "cli_yyy",
        "appSecret": "***",
        "domain": "feishu",
        "allowFrom": ["ou_yyy"],
        "cwd": "/home/me/life"
      }
    ],
    "seq": 2
  }
}
```

- `instanceId`：账号唯一标识，规则为「平台名」或「平台名:序号」：**旧配置迁移来的首个账号**沿用平台名（`feishu`）；**面板上新增的账号**一律带序号（`feishu:1`、`feishu:2`…，序号在该平台内只增不复用，避免复用已删除账号的编号导致会话/白名单串号）。因此全新安装后添加的第一个飞书账号是 `feishu:1`，已有单账号配置升级后再添加的第二个账号是 `feishu:2`。
- `seq`：该平台已分配的序号计数，用于避免复用已删除账号的编号。
- **旧配置自动迁移**：升级后首次启动会把原来的单账号对象无损转成 `accounts: [{ instanceId: "feishu", ...原字段 }]` 并写回一次，凭证与其他配置不会丢失；旧版本客户端/备份导入仍可读。

## ❓ 常见问题

**Q：两个账号能用同一个飞书应用吗？**
A：不能。飞书同一应用只能维持一条长连接，保存时会直接拒绝并提示与哪个账号冲突。

**Q：账号数会影响性能吗？**
A：每个账号是一条独立长连接 + 一套会话桥，正常使用 2–3 个几乎没有感知；上限 10 个。

**Q：删掉账号会丢会话吗？**
A：不会。只删除该账号的机器人与归属配置，DSH 会话本身保留。

**Q：备份导出会包含所有账号吗？**
A：会。备份导出的是完整 `config.json`，其中包含全部账号；导入后按新结构恢复，旧格式备份同样兼容。
